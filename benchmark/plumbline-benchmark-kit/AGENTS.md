# Benchmark controller repository

This repository controls benchmark campaigns. It is not one of the evaluated projects.

When asked to run the benchmark, invoke or read `.agents/skills/plumbline-benchmark/SKILL.md`. Do not invoke Plumbline initialization in this controller repository. Do not solve task fixtures in this chat. Only fresh Codex app-server sessions launched by `bench.py` may produce scored candidate implementations.

The user-authorized work is staging disposable projects, using existing authenticated Codex access, running the bounded selected matrix, and reporting evidence. Never edit personal/global configuration, unrelated repositories, operating-system security settings, or authentication files in place. Never print credentials or silently increase spend limits. A hook's existence is not proof it executed.

Read docs/HOST_SETUP.md for actual host discovery and docs/TELEMETRY.md before accepting cost results. Ordinary path/tool discovery and disposable setup are your responsibility, not questions for the user. Only missing login, native hook trust, a security expansion, or a genuinely unknown custom hook should require a focused user action.

Freeze before scoring. Never tune fixtures, prompts, acceptance tests, or role profiles in response to model failures within a campaign. Never pass reference solutions or external grader output into candidate contexts. Host-adapter repairs before a new freeze are allowed with explicit disclosure, offline tests, and a new campaign identifier.

Do not confuse a quiet candidate with a failed candidate. Observe the runner process, logs, and heartbeat. Do not restart a live process or silently replace a failed attempt. Report partial campaigns honestly when budgets or host problems stop execution.
