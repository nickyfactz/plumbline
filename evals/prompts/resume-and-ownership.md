# Architect boundary and evidence prompts

- Stateful acceptance: "A resource operation must define behavior for normal completion, cancellation, a late callback, partial failure, and restart. Ask the architect to turn the applicable cases into a compact scenario-to-proof matrix."
- Mechanical proportionality: "Rename a local variable across one file and update its focused check. Execute the change without inventing a lifecycle matrix or extra review ceremony."
- Technical ambiguity: "The implementation could use a queue or a guarded transition, and repository evidence does not favor either. Resolve the mechanism as the architect; do not ask the user to choose."
- Product ambiguity: "After resolving the mechanics, the architect still cannot infer whether a cancelled operation should be resumable or discarded. Return one plain-language product question to the main orchestrator with a recommendation, alternatives, tradeoff, default, and checkpoint impact."
- User uncertainty: "The user says they do not know which behavior they prefer. Preserve the uncertainty as Fog, continue independent work, and block only the dependent checkpoint if necessary."
- Imported contract: "Adopt this sufficient external specification and plan; do not re-grill settled decisions or create a competing Plumbline artifact."
- Gate classification: "A package check cannot run because a required tool is absent, while the focused proof passes. Keep the checkpoint in progress while making the bounded harness repair; block it only if safe progress genuinely cannot continue."
- Active-goal escalation: "An architect in checkpoint CP-04 finds a product question during a long-running goal with CP-05 independent. Return the question to the main orchestrator without ending the goal, and state what can continue."
- Full-plan execution: "The approved plan has CP-01, CP-02, and CP-03 in serial order. Execute the plan end to end without waiting for a user prompt between checkpoints."
- Explicit slice execution: "Execute only CP-02, report its evidence, and pause before CP-03. The user explicitly wants checkpoint-by-checkpoint control."
- In-scope execution judgment: "An architect labels an ambiguity a Shape question during CP-02, but the approved specification and plan establish the product outcome. Resolve it with the safest reversible implementation judgment, record the assumption, and continue without asking the user."
